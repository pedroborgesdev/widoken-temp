# Security

Both renderers run with `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true`. The widget and dashboard use separate preloads: the widget receives only overlay, provider, settings, and dashboard-open operations; the dashboard receives provider, settings, theme-sync, dashboard-window, DeepSeek credential, and quit operations. Neither exposes `ipcRenderer`, filesystem access, process execution, or arbitrary channel names. The DeepSeek credential API exists only on the dashboard preload; the widget cannot read or write a key.

Main-process handlers validate and clamp interaction rectangles and sanitize all persisted settings. Settings are atomically replaced and written with mode `0600`.

Provider credentials are handled only in the main process. Adapters may borrow an existing local session (Claude Code, Codex, Cursor, Antigravity, GitHub CLI). For DeepSeek there are two sources:

- **Harness account** — the dashboard performs a local, read-only check of the grant record in `~/.dsh/.credentials.yaml` (or `DSH_HOME/.credentials.yaml`) so it can show whether the account is available when it opens. The token stays in the main process and the adapter uses it solely as the `x-dsh-auth-token` header of the platform summary request, which is only issued while DeepSeek is enabled. The file is parsed read-only with js-yaml's safe schema, only the `https://platform.deepseek.com` issuer is accepted, and Widoken never writes to it.
- **API key** — `DEEPSEEK_API_KEY` from the process environment as a compatibility fallback, or a key the user saves in the dashboard. A saved key is encrypted with Electron `safeStorage` before insert and decrypted only in the main process; it is stored as a `BLOB` in the `provider_credentials` table of `analytics.sqlite` and never appears in plain text in SQLite, `settings.json`, snapshots, logs, or errors. Credential IPC handlers return only non-secret status booleans (`storedApiKeyConfigured`, `environmentApiKeyAvailable`, `harnessAccountAvailable`), and the renderers never receive the stored key. Runtime encryption fails closed when `safeStorage.isEncryptionAvailable()` is false, and on Linux when `getSelectedStorageBackend()` reports `basic_text`.

Neither credential is logged, embedded in a provider snapshot or error message, or sent over IPC. The only persisted DeepSeek quota state is the observed baseline per auth source and currency (capacity, last remaining balance, and a format marker) in `deepseek-balance.json`, written atomically with mode `0600` where the platform supports it and containing no credential. A real adapter must keep tokens outside React and should use Electron `safeStorage` or an OS credential store for anything that must persist. The documented session and credential files (Claude Code, Codex, Cursor, GitHub CLI, and the DeepSeek harness) are read only in the main process and are never modified; the DeepSeek harness token is used for balance requests only while DeepSeek is enabled.

Hugging Face is disabled by default and its provider settings make browser-session access explicit. Once enabled, the main process launches the bundled Python collectors, which ask `browser-cookie3` only for `huggingface.co` cookies in the selected browser. The cookies stay in the collector process, are used only for direct HTTPS requests to Hugging Face, and are never logged, persisted by Widoken, placed in a snapshot, or exposed through IPC. Widoken persists only the USD observed baseline in `huggingface-balance.json`. An optional `HF_TOKEN` is used solely to verify that it belongs to the same account as the browser session; it is not used as a fallback credential or stored by Widoken.

VS Code theme sync runs only after the user presses the sync button. The main process reads VS Code's local user/Profile settings, installed extension manifests, and the selected color-theme file. It does not read source files or send theme data over the network; only the resolved theme name and validated hexadecimal colors are persisted.

The Codex and Cursor activity probes read local rollout and agent-transcript JSONL files and retain only the latest start/completion state, byte offset, and modification time for each recent file. Antigravity reads its local presence locks and transcript boundaries. While Harness or Automatic credential mode is selected, DeepSeek follows the Harness's compressed session log and retains only its latest `turn/start`/`turn/end` state, byte offset, and modification time. Hugging Face compares only monthly request counts returned by its billing endpoint and emits `working`, `idle`, or `unknown`; request content is never collected. Message text and tool output are not logged, persisted by Widoken, or sent to a renderer; renderers receive only `active` or `idle`.

Production dependencies currently have no known npm audit findings. Build-only transitive advisories should be reviewed before each release, along with Electron updates.
